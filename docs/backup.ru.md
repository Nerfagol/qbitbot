# Резервное копирование и восстановление

Копии содержат личные ID чатов и настройки доступа. Храните их вне Git, ограничьте
доступ и сохраните ещё одну зашифрованную копию отдельно от сервера.

## Состояние бота

`backup_state.py` использует SQLite online backup, включая подтверждённые данные
WAL, и проверяет целостность и SHA-256. Каждая база согласована отдельно; три базы
не образуют одну общую транзакцию. Для общего спокойного состояния остановите бот:

```sh
docker compose stop bot
docker compose run --rm --no-deps bot python backup_state.py \
  --watch-db /state/watches.sqlite3 --destination /state/backup-2026-09-27
mkdir -m 700 backups
docker compose cp bot:/state/backup-2026-09-27 backups/
docker compose up -d bot
```

Каждый раз выбирайте новый каталог: существующий не перезаписывается. Копируются
`watches.sqlite3`, доступные `health.sqlite3` и `preferences.sqlite3`, а также
`manifest.json`. Отсутствие необязательных баз отмечается явно. База наблюдений
должна уже существовать. Файлы загрузок и пароли сервисов в эту копию не входят.
Для режима только бота добавляйте `-f compose.bot-only.yaml` к командам Compose.

## Настройки сервисов и файлы

Отдельно сохраните `.env`, `bot.env`, переопределения Compose и текущую версию Git.
Перед копированием полных каталогов настроек остановите сервисы:

```sh
docker compose stop bot qbittorrent jackett
docker compose cp qbittorrent:/config backups/qbittorrent-config
docker compose cp jackett:/config backups/jackett-config
chmod -R go-rwx backups
docker compose up -d
```

В настройках есть ключи доступа и состояние торрентов. Каталог скачанных файлов
копируйте отдельно: команды выше его не включают. Сохраните соответствие путей
каталогу `/downloads` внутри qBittorrent. Для внешних сервисов нужны аналогичные
копии их настроек.

## Обновление и откат кода

Сохраните предыдущую версию/образ и проверенную личную копию. Остановите бот,
выберите нужный релиз, соберите образ и выполните `docker compose up -d --no-deps bot`.
Для режима только бота используйте его Compose-файл. Обычный откат кода сохраняет
текущее состояние, а не восстанавливает старые базы. Схема наблюдений v1 совместима
с исходной публичной версией; языковые настройки хранятся отдельно и сохраняются.

**Не используйте `docker compose down -v` для обновления: команда удаляет тома
состояния и настроек.** Нельзя запускать два бота с одним Telegram-токеном.

## Намеренное восстановление старой копии

Остановите бот и сначала сохраните текущее состояние. Проверьте SHA-256 из
`manifest.json` и `PRAGMA integrity_check` каждой базы. Восстанавливайте в **новый**
закрытый каталог/том, не поверх работающей базы. Для стандартного `/state`:

| Имя в копии | Рабочее имя |
| --- | --- |
| `watches.sqlite3` | `watches.sqlite3` |
| `health.sqlite3` | `watches.health.sqlite3` |
| `preferences.sqlite3` | `watches.preferences.sqlite3` |

При другом `WATCH_DB_PATH` используйте соответствующие соседние имена. Права:
каталог 700, файлы 600; владелец должен позволять контейнеру читать и записывать.
Подключите новый том через проверенное переопределение Compose, запустите один бот
и проверьте Загрузки, Состояние и Язык. Старый том сохраните до проверки.
Старая копия намеренно теряет более поздние подписки и может повторно отправить
уведомления: доставка гарантирует повторные попытки, но не отсутствие дублей.

`make integration-public` проверяет чистую установку, замену контейнера, откат
публичного кода и восстановление в новый том на полностью искусственных данных.
